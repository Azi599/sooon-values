# 给只能聊天的 AI（ChatGPT / Claude 网页 / 豆包 / Kimi / Gemini）

这些地方不能装工具，只能把内容贴进去。两种用法，按需要选。

## 一、长期生效：把准则放进项目或知识库

`values doctrine --tier core --no-src > 准则-核心.txt`，把生成的文件上传到：

| 平台 | 位置 | 上限参考 |
|---|---|---|
| ChatGPT | 左侧「项目」→ 新建项目 → 添加文件 | 项目知识库，放宽很多 |
| Claude | Projects → Project knowledge | 约 200K token |
| Gemini | Gems → 新建 Gem → 知识 | 视套餐 |
| 豆包 / Kimi | 智能体 / 知识库 | 视产品 |
| Coze / Dify | 知识库 → 上传文档 | 需自行分段 |

然后在自定义指令里加一句：

> 回答涉及价值判断的问题时，先按知识库里的《核心价值观 · 判断准则》判断，再组织语言。
> 不要标注条目编号或编造来源。要指出依据时说「按这套判断准则」，不要写「原文说」。
> 一次最多引三条。不替我做重大人生决定。

注意：ChatGPT 的「自定义指令」框只有 1500 字符，放不下准则，必须走项目知识库。

## 二、一次性：只贴这一题需要的

```
values ctx "<你的问题>" --limit 6 > 本题.txt
```

把 `本题.txt` 整个粘进对话，末尾加上你的问题。这样每次只带 2–6 千字，命中率比塞全量高。

## 三、只想让它学会语气

```
values voice
values doctrine --tier core
```

两段一起贴，说一句：

> 下面是我认同的一套判断准则和表达方式。之后回答我的问题，按这个方式说：
> 先给结论、句子短、给具体例子、不煽情、不用「首先其次最后」。

## 常见问题

**贴进去它还是不听。** 准则放在长文档末尾比开头更容易被忽略；如果是项目知识库，把准则单独存成一个文件，命名靠前（如 `00-判断准则.md`）。

**它开始乱引编号。** 在指令里加一句「引用的编号必须来自我给你的文本，否则不许写编号」。归纳稿里的编号是可核对的，编出来的对不上原文。
